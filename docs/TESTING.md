# Тестирование IMPOSSIBLE PENALTY

Проверяем отдельно чистую игровую логику, интеграцию браузерного интерфейса со сценой и визуальный результат. Успешная сборка сама по себе не подтверждает работоспособность анимации и управления.

## Команды

Из корня проекта:

```bash
npm run typecheck
npm run lint
npm run format:check
npm run test
npm run build
npx playwright install chromium firefox webkit
npm run test:e2e
```

Зависимости устанавливаются через `npm install`, в CI — `npm ci` с `package-lock.json`. Для первого запуска Playwright нужны браузерные бинарные файлы. В Linux системные зависимости устанавливаются командой `npx playwright install --with-deps chromium firefox webkit` при наличии нужных прав. Результаты Playwright и скриншоты не входят в production-сборку.

## Модульные проверки

- Границы интервалов `[0, .50)`, `[.50, .75)`, `[.75, .90)`, `[.90, 1)` соответствуют Predictor, Flash, Showoff и голу.
- Невалидное значение генератора случайных чисел отклоняется, координаты прицела ограничиваются допустимым диапазоном.
- Большая выборка с воспроизводимым генератором подтверждает распределение около 50/25/15/10. Проверка не требует ровно одного гола из каждых десяти ударов.
- Память направлений и выбор реплики не меняют исход удара и не расходуют дополнительное случайное число.
- Счётчики сохраняют инвариант `shots = goals + saves`; гол сбрасывает текущую серию сейвов, лучшая серия не уменьшается.
- Хранилище восстанавливает корректные настройки, отвергает повреждённые и противоречивые данные, выдерживает отсутствие доступа к `localStorage`.

## Браузерные и интеграционные сценарии

- Нажатие или касание внутри ворот запускает один удар. Клики вне ворот ничего не меняют.
- Очень быстрые повторные клики и ввод во время анимации не запускают дополнительные удары; статистика обновляется один раз после разрешения эпизода.
- Состояния `ready → runup → flight → result → ready` завершаются, после каждого эпизода можно снова бить.
- Стрелки перемещают прицел, Enter и пробел бьют после фокусировки поля. Удержание клавиши не создаёт новую серию ударов.
- Показатели и настройки восстанавливаются после перезагрузки. Сброс требует подтверждения; отмена сохраняет данные.
- Диалог статистики удерживает фокус, закрывается по Escape и возвращает фокус; при открытом диалоге поле не принимает удары.
- Управление звуком и уменьшением анимаций сохраняется; при запрете хранилища игра остаётся доступной.
- Resize, узкий мобильный экран и смена ориентации сохраняют пропорции сцены и попадание прицела.
- При уходе вкладки в фон эпизод приостанавливается; после возвращения завершается корректно.
- В консоли отсутствуют необработанные ошибки и ошибки загрузки ресурсов.

Конфигурация Playwright определяет фактически запускаемые проекты браузеров и устройств. Обнаруженная проблема исправляется вместе с регрессионной проверкой, когда автоматизация надёжно воспроизводит её.

## Визуальная проверка

В браузере осматриваем стадион и интерфейс на desktop и мобильной ширине. Снимки экрана помогают сравнивать пропорции ворот, чёткость пикселей, читаемость показателей и отсутствие обрезанных элементов. Анимацию дополнительно проверяем в движении:

- носок футболиста касается мяча в момент удара;
- мяч уменьшается по мере удаления и летит к выбранной точке;
- при сейве перчатка достигает мяча до отскока, без телепортации;
- при голе мяч достигает сетки, запускаются реакция сетки и празднование;
- необычные позы вратаря не оставляют сломанную позу в следующем эпизоде;
- reduced motion уменьшает декоративное движение, сохраняя понятный ход удара;
- эффекты и фоновая атмосфера не мешают следить за мячом.

Цель — 60 FPS на обычном современном устройстве. Скорость анимации зависит от прошедшего времени, а не от количества кадров. Прохождение E2E не является измерением FPS или гарантией одинаковой производительности на каждом устройстве.

## CI и границы подтверждения

GitHub Actions устанавливает зависимости из lockfile, запускает ESLint, Prettier, TypeScript, Vitest, production-сборку и Playwright. При ошибке сохраняет результаты Playwright в артефактах. CI не публикует игру и не настраивает GitHub Pages.

Фактический успешный запуск определяется результатами команд и статусом workflow для конкретного коммита. Этот документ описывает стратегию проверки; не подменяет журнал запуска и не заявляет неподтверждённую совместимость. Chromium, Firefox и WebKit в Playwright покрывают основные движки; настоящий Safari на macOS/iOS и реальные мобильные устройства требуют отдельного прогона.
